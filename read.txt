CONTENT ORCHESTRA - BUILD LOG


--- PHASE 1: PROJECT SETUP ---

/ initialize node project -> npm init -y 
/ install core dependencies -> npm install fastify zod dotenv
/ install TypeScript and dev dependencies -> npm install -D typescript @types/node tsx
/ initialize your TypeScript configuration -> npx tsc --init
/ "strict": true and "target": "ES2022" are set in your tsconfig.json for optimal modern Node support
/ in package.json -> "type": "module"

--- PHASE 2: AI SDK SETUP ---

/ npm install ai @ai-sdk/google
/ create .env file -> add GOOGLE_GENERATIVE_AI_API_KEY with your API key
/ import 'dotenv/config' in server.ts to load environment variables automatically

--- PHASE 3: SCHEMAS (THE SAFETY LAYER) ---

/ define the Evaluator's Zod Schemas (The Safety Layer)
/ create src/schemas/compliance.ts -> ComplianceReviewSchema with zod
    - status: enum ['APPROVED', 'REJECTED', 'NEEDS_REVISION']
    - confidenceScore: number (0-100)
    - flaggedIssues: optional array of strings (brand/safety violations)
    - suggestedFixes: optional array of strings
    - finalOutput: optional string (the approved content)
/ export ComplianceReview type using z.infer for type safety

--- PHASE 4: AGENTS (THE BRAIN) ---

/ Knowledge Agent: Gathers facts or context (e.g., searching a database or the web).
    - create src/agents/knowledge.ts
    - define ContentBriefSchema inline with zod (coreMessage, targetAudience, keyFeatures)
    - uses generateObject() from Vercel AI SDK to force structured JSON output
    - takes raw internal data and extracts a clean brief for the Creator

/ Creator Agent: Uses those facts to write the actual content (a blog post, ad copy, etc.).
    - create src/agents/creator.ts
    - uses generateText() from Vercel AI SDK for free-form content generation
    - accepts a ContentBrief + optional previousFeedback for revision loops
    - temperature set to 0.3 for consistent, professional output
    - when feedback is provided, injects STRICT REVISION RULES into the prompt

/ Governance Agent: Reviews the draft for brand safety and compliance. (This is the "Brand Guardian").
    - create src/agents/evaluator.ts
    - uses generateObject() with ComplianceReviewSchema to return structured evaluation
    - temperature set to 0.1 for deterministic, strict safety checks
    - enforces rules: no aggressive sales phrases, no unverified claims, professional tone only
    - banned words: "Buy now", "Limited offer", "Cheap", "Hurry", "best", "fastest", etc.

--- PHASE 5: ORCHESTRATOR (THE SERVER) ---

/ server -> fastify + zod + dotenv
/ create src/server.ts -> the central orchestrator that wires all agents together
    - GET / -> health check endpoint
    - POST /api/orchestrate -> the main pipeline endpoint
/ orchestration flow:
    1. Knowledge Agent synthesizes raw data into a structured brief
    2. Creator Agent drafts content based on the brief
    3. Governance Agent evaluates the draft for compliance
    4. if NEEDS_REVISION -> feedback loop: pass flagged issues back to Creator (max 3 attempts)
    5. 5-second delay between retries to avoid API rate limits
    6. return success with final approved draft OR failure with last evaluation

--- PHASE 6: RUN & TEST ---

/ npx tsx src/server.ts -> starts the server on http://localhost:3000
/ test with PowerShell:
    Invoke-RestMethod -Uri http://localhost:3000/api/orchestrate -Method Post -ContentType "application/json" -Body '{"rawData": "your internal memo here"}'
/ pipeline runs successfully:
    - Knowledge Agent extracts brief from raw data
    - Creator writes initial draft
    - Evaluator flags issues (e.g., "redefine enterprise data speed" -> unverified claim)
    - Creator revises based on feedback
    - Evaluator approves revised draft
    - Response: { status: "success", finalStatus: "APPROVED" }
